# Physician-to-Voter Linkage

Matches physicians in NPPES to registered voters in the L2 voter file, so that
voter-file-derived attributes can be appended to physician records. Annual extracts span
2018–2025.

Matching is a trained random forest over candidate pairs generated by locality-sensitive
hashing on name. A older rules-based flow-diagram matcher has been removed; see
`figures/processing.png` for what it used to do.

> **The L2 voter file is licensed.** It stays on the HPC and must never be committed to this
> repository. NPPES and the CMS/NBER inputs are public.

## Layout

```
.
├── _targets.R              pipeline definition -- read this first
├── R/                      all target functions, flat and unnumbered
├── scripts/                standalone, side-effecting scripts (not targets)
├── tests/                  one self-contained test script, no real data needed
├── trunk/                  data root; everything inside is gitignored
│   ├── raw/                inputs the pipeline reads but does not produce
│   ├── derived/            everything the pipeline writes
│   └── analysis/           analysis outputs
├── docs/                   mkdocs source, published to GitHub Pages
├── figures/                diagrams and pipeline figures
├── job_outputs/            SLURM and crew worker logs (gitignored)
├── submit.sh               sbatch script for the full 2018-2025 run
└── small_submit.sh         sbatch script for a scoped pilot run
```

`R/` holds **only function definitions** — `targets::tar_source()` loads the whole directory,
so anything that executes at load time belongs in `scripts/`.

## Running it

The pipeline is a [targets](https://books.ropensci.org/targets/) graph, so read `_targets.R`
rather than the individual scripts to understand execution order. `targets::tar_visnetwork()`
or `tar_manifest()` is the fastest way to orient.

```r
targets::tar_make()
```

On the HPC, submit rather than running interactively:

```bash
sbatch submit.sh
```

Outputs, once built:

```r
targets::tar_read(physician_matches)             # one row per physician, best match
targets::tar_read(physician_year_panel_data)     # one row per physician-year
targets::tar_read(physician_year_panel_filled)   # the panel with confident gaps filled
targets::tar_read(panel_gap_summary)             # how many gaps, and why each was filled
```

**No `match_prob` cutoff is applied anywhere.** Every physician with any candidate appears,
however weak the match — thresholding is left to whoever consumes the output.

## Tests

```bash
Rscript tests/test_l2_and_geography.R
```

Self-contained: it builds its own synthetic L2 hive tree in a temp directory, so it needs no
real data and writes nothing inside the repo.

## Dependencies

There is no lockfile. Packages must be present in the R library of whatever environment the
pipeline runs in; the direct dependencies and the versions they have been validated against
are listed in `CLAUDE.md`.

## Documentation

Fuller documentation is in `docs/`, published with mkdocs — pipeline steps, replication
instructions, and the matching methodology.
